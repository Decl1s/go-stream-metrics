# Потоковые метрики на Go

Учебный проект дата-инженера от 17 октября 2026 года. Читает JSONL построчно,
проверяет строки и считает запросы, ошибки и задержки по сервисам. Исходные события
не накапливаются в памяти. Новый инструмент серии — **Go 1.27.2**, только стандартная библиотека.

[Подробный конспект](NOTES.md) · [Технологии](TECHNOLOGIES.md) · [Проверки](VALIDATION.md)

## Запуск за пять минут

Нужен Go **1.27.2 или новее** с [официального сайта](https://go.dev/dl/).
Из папки проекта:

```sh
go run ./cmd/streammetrics demo
go run ./cmd/streammetrics run
go run ./cmd/streammetrics run -json -output workspace/summary.json
```

Ожидаются 10 005 входных строк, 10 000 принятых, 5 ошибочных и 3 сервиса.
Итого: 500 ответов 5xx, 300 ответов 4xx, 5010 медленных запросов при пороге 500 мс.
Для каждого сервиса p95 находится не выше 1000 мс.
`workspace/requests.jsonl` — синтетический вход, `workspace/summary.json` — результат.

Демо и сохранение результата **не заменяют существующие файлы**.
Повторяйте `run` без `-output` или указывайте новое имя. Сам повтор обрабатывает файл
с начала и не прибавляет показатели к прошлому результату. Повторный `demo` в тот же файл
завершится понятной ошибкой; выберите другой путь, если нужен новый набор.

При локальной установке Go в `.tools/go/` используйте `.tools/go/bin/go` на Linux
или `.tools\go\bin\go.exe` на Windows вместо `go`. Папка `.tools` в исходный архив не входит.
Пользовательское окружение и зависимости приложение автоматически не устанавливает.

## Отдельный исполняемый файл

```sh
go build -trimpath -buildvcs=false -o workspace/streammetrics ./cmd/streammetrics
```

Linux: `./workspace/streammetrics help`. На Windows укажите при сборке
`-o workspace/streammetrics.exe`, затем ` .\workspace\streammetrics.exe help`.
После сборки для запуска самой программы компилятор Go и Python не нужны.
Готовый бинарный файл создаётся локально; исходный релиз содержит только исходники.

## Что считает программа

По каждому сервису сохраняются число запросов, 5xx, отдельные 4xx, доля 5xx,
средняя задержка, число медленных запросов и десять непересекающихся интервалов задержки.
Верхние границы интервалов в миллисекундах:

```text
50, 100, 250, 500, 1000, 2500, 5000, 10000, 30000, 60000
```

Первый интервал включает 0 и 50; следующий — значения больше 50 и не больше 100,
и так далее. Поле `p95_upper_ms` — **верхняя граница интервала**, в который попал
элемент с рангом `ceil(0.95 × N)`. Это приближённая оценка и другой способ расчёта,
чем линейный перцентиль в предыдущем проекте на Polars.
Для задержек 100, 200 и 300 мс результат здесь — `p95_upper_ms = 500`, среднее — 200.

Все суммы считаются целыми числами; среднее и процент округляются до двух знаков.
SHA-256 относится к полным прочитанным байтам, включая ошибочные строки и переводы строк.
Имена сервисов в результате отсортированы. Идентичный повтор даёт тот же JSON.

## Контракт входа

Одна физическая строка UTF-8 без BOM — один JSON-объект ровно с тремя полями:

```json
{"service":"api","status":200,"duration_ms":125}
```

| Поле | Правило |
| --- | --- |
| service | 1–32 ASCII-символа: первая строчная буква, затем буквы, цифры, `_` или `-` |
| status | Целое число 100–599 |
| duration_ms | Целое число 0–60 000 |

Числовая запись — обычные цифры, без дроби, экспоненты и знака.
Строки вместо чисел, bool, null, неизвестные и повторяющиеся ключи запрещены.
Пустая строка считается ошибочной. Последняя строка может не иметь перевода строки;
LF и CRLF поддерживаются. Неверный UTF-8 считается ошибкой строки.

Неверная строка увеличивает один из кодов `json`, `schema`, `service`, `status`,
`duration_ms`; исходная строка и её значения не сохраняются. Учитывается первая
обнаруженная причина, а не все возможные ошибки одной строки.

**Удаления дублей нет:** одинаковые строки считаются отдельными событиями.
Нет идентификаторов запросов, временных окон, истории или инкрементальной загрузки.
Для точного удаления дублей понадобилось бы отдельное ограниченное или внешнее хранилище.

## Пределы и сбои

- Строка — не более 8192 байт после удаления LF/CRLF; вход — до 2 ГиБ и 100 млн строк.
- По умолчанию до 64 различных сервисов; `-max-services` допускает значения 1–1024.
- Порог медленного запроса: `-slow-ms`, от 0 до 60 000 мс, включительно.
- Ошибка чтения, превышение размера строки, входа или числа групп отменяет весь результат.

```sh
go run ./cmd/streammetrics run -input workspace/requests.jsonl -max-services 10 -slow-ms 1000
```

Основное состояние ограничено длиной строки и числом групп с фиксированными счётчиками.
Это **не жёсткая гарантия максимального RSS** процесса: выделения JSON, сборщик мусора
и среда исполнения также используют память. Локальные замеры записаны в VALIDATION.md.

Вход должен быть обычным файлом. Символические ссылки в выбранных путях отклоняются.
Не меняйте вход во время обработки: согласованный снимок внешнего изменяемого файла
не обеспечивается. Параллельный запуск не является способом распределённой обработки.

Файл `-output` создаётся только после успешного чтения и расчёта, с исключительным
созданием. При обрабатываемой ошибке записи программа закрывает и пытается удалить
свой незавершённый файл. Это не атомарная публикация для параллельных читателей:
не читайте файл до успешного завершения команды. Авария питания или принудительное
завершение могут оставить незавершённый файл; используйте новое имя и проверьте JSON.
Ранее существовавшие файлы программа не перезаписывает.

## Проверки

```sh
go test ./...
go vet ./...
python scripts/smoke_check.py
python -m unittest discover -s tests -v
python scripts/check_public.py
```

Python 3.11–3.12 нужен только для проверки, упаковки и воспроизводимого сценария демо;
его сторонних зависимостей нет. При нестандартном пути Go:
`python scripts/smoke_check.py --go .tools/go/bin/go`.
Проверка создаёт временный набор, собирает инструмент, сверяет результаты и повтор,
затем проверяет отказ при попытке заменить результат.

## Исходный архив и приватность

```sh
python scripts/package_release.py
```

Создаются `artifacts/go-stream-metrics-0.1.0.zip` и `artifacts/SHA256SUMS`.
Состав задан в `PUBLIC_FILES.txt`. Архив не включает `.tools`, `.cache`, Git, бинарные
файлы, входные журналы и результаты из `workspace`. Генератор использует только константы,
не читает документы, профиль, окружение или настоящие журналы пользователя.
Приложение не отправляет данные по сети и не создаёт фоновые сервисы.

Проверка публикации ищет контакты, типичные секреты и локальные пути в исходниках,
запрещает лишние отслеживаемые файлы. Это вспомогательная проверка, а не аудит любого
будущего содержимого. Настоящие журналы и их сводки не публикуйте.
Адреса авторства публичной истории GitHub видны посетителям репозитория;
проверка отмечает адреса вне no-reply без вывода самих адресов. Контакты в исходниках запрещены.
